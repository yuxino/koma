# Koma 逐帧研究室（Frame Atelier）实现设计

状态：**设计已采用**
日期：2026-08-24
范围：公共应用、任务进度、结果回看、管理后台、弹窗、响应式界面与品牌资产使用

本文件定义 Frame Atelier 的实施目标和验收边界，不表示每项要求已经由代码完成。实现不得新增或暗示 Koma 当前不存在的产品能力。

## 1. 背景与目的

Koma 的核心任务不是“展示 AI”，而是把一段视频变成用户可以阅读、定位、复制、下载和再次打开的内容。现有功能已经覆盖视频输入、语音与画面分析、总结、章节、标签、字幕、关键帧、结构化提取、文件产物、持久回看与管理配置。视觉重构需要让这些能力形成一条清楚的工作流，而不是继续叠加营销区块和独立卡片。

Frame Atelier 把产品理解为一张逐帧整理台：视频进入工作台，声音与画面被沿时间码拆解，结果再以摘要、时间线、字幕和文件形式归档。全新的 Q 版角色提供亲和力和记忆点，界面本身保持克制、可读和高效。

## 2. 目标

1. 让“视频 → 声音与画面 → 数据与文件”的处理逻辑在首页、进度和结果中保持连续。
2. 建立与 Koma 功能直接相关、从零设计的 2～2.5 头身 Q 版角色，优先保证小尺寸 Logo 识别。
3. 用一个明确的令牌和组件系统统一公共界面、结果、弹窗与后台。
4. 让分析表单、视频、时间轴和结果内容始终高于装饰与营销文案。
5. 在 320px 起的移动端、键盘操作、减少动态效果和高对比需求下保持完整可用。
6. 让用户用自然语言描述目标，由 AI 整理出可编辑、可复用的 JSON 结构，而不必为每次测试重复输入。
7. 除新增 JSON 结构生成接口外，不改变视频分析接口、数据结构和权限模型。

## 3. 非目标

- 不新增账号、团队、评论、收藏、分享权限或协作功能。
- 不新增分析模型、Provider、输出格式或服务端处理阶段。
- 不修改任务所有权、持久化、删除范围、下载地址或回看链接规则。
- 不把 Koma 改造成营销落地页、暗色剪辑软件仿制品或角色互动产品。
- 不沿用、微调或临摹旧 Logo 的角色脸型、发型、服装、姿态、裁切和轮廓。
- 不用虚构的示例指标、处理速度、准确率或用户评价填充页面。

## 4. 设计原则

### 4.1 工作台优先

首页第一视区必须让用户看见并理解输入与开始动作。标题、角色和说明为工作台服务，不能把表单推到首屏之外。结果页以内容导航和回到时间点为核心，不为视觉效果打断阅读。

### 4.2 Q 版但不幼稚

角色采用圆润大头、小身体、简化四肢的 2～2.5 头身比例。可爱感来自清晰轮廓、表情和动作，不来自粉紫配色、幼儿化语言或夸张装饰。角色服装和道具围绕影像整理重新设计，不使用校服、裸露或 fan service。

### 4.3 时间码是一等视觉元素

时间码、播放头、取景框角、影片接触印样和音频波形可以成为结构标记。它们必须对应真实内容或导航，不作为无意义背景纹理。

### 4.4 中性基底，克制强调

页面以暖纸、墨黑、中性灰为主。酸性青柠是现有品牌色，只表示当前、选中、进度和关键动作。失败使用暖红，警告使用琥珀；状态色不扩张为主题色。

### 4.5 同一产品，不同密度

公共界面、结果页和后台共享令牌、按钮、表单、焦点和弹窗规则。后台可以更密集，但不能形成另一个视觉产品；角色在后台只承担品牌识别，不进入数据表格。

## 5. 视觉概念

### 5.1 关键词

逐帧整理、暖纸工作台、接触印样、时间码、Q 版助手、安静、精确、轻盈。

### 5.2 主要视觉语法

- 1px 暖灰分隔线组织区块。
- 较大的排版与留白负责一级层级，黑色实心动作负责主操作。
- 暗色媒体舞台与浅色工作区形成明确边界。
- 等宽时间码标记视频位置、处理阶段和技术元数据。
- 取景框角与播放三角只用于品牌标记、选择和定位。
- 阴影仅用于需要从当前平面抬起的菜单、弹窗和预览层。

### 5.3 明确排除

不使用装饰性渐变、玻璃拟态、彩色大背景、霓虹发光、拟物胶囊、成排功能卡、虚假软件外壳、无意义网格、视差和连续漂浮动画。视频字幕可以使用实色或半透明深色衬底保证可读性，但不使用装饰性渐变。

## 6. 角色与 Logo 资产体系

### 6.1 从零设计要求

新角色不是旧 Logo 的 Q 版重绘。不得复用旧角色的五官比例、发型轮廓、服装结构、配件位置、画面裁切或招牌姿态。设计评审时必须并排检查新旧轮廓；即使去掉颜色，也应一眼看出是新的角色系统。

### 6.2 角色定位

角色名称沿用 Koma，身份是“逐帧整理员 / Frame Assistant”。她负责看画面、听声音，并把真实分析结果按时间码整理出来。角色不承诺模型以外的新能力，也不作为会话机器人。

造型规则：

- 全身比例为 2～2.5 头身；头部约占总高 40%～50%，身体短小，手脚简化。
- 头部接近圆形，黑发双丸子形成稳定外轮廓；笑眼与小口在 32–64px 仍可读。
- 发型、服装和整体外轮廓必须从零建立；不以任何旧角色图层、线稿或提示词为底稿。
- 服装使用墨黑、象牙白和暖灰的大色块，减少细碎拉链、肩章和纹理。
- 以手边的黑色胶片卷作为主要识别道具，以右侧丸子头上的播放标记连接产品功能。
- Acid-lime 只出现在这个小型播放标记上，保证黑白状态仍能通过双丸子轮廓和胶片卷识别。
- 姿态为低重心跪坐，圆润、稳定，始终保持 Q 版全身比例，避免长腿与复杂手势。

角色在首页承担品牌说明，在进度页承担轻量陪伴，在结果和后台数据区不反复出现。任何状态都必须由真实文字、百分比和控件表达，不能只依赖角色表情。

### 6.3 Logo 架构

Logo 以小尺寸为起点，而不是先画大插图再缩小。

1. **Micro mark**：16–24px，只保留头部外轮廓与一个取景框/播放头识别点，不出现身体和细节纹理。
2. **App icon**：32–64px，使用 Q 版头部或头部加极简上身；大眼、脸缘和识别道具必须清楚。
3. **Character mark**：128–512px，完整展示 2～2.5 头身小身体与胶片卷，适合进度和 README。
4. **Mascot illustration**：首页使用透明背景完整 Q 版角色，可以携带一个与逐帧整理相关的简单道具，但仍保持相同头身比例。
5. **Wordmark**：界面中的 “Koma” 保持真实文本；不把文字烘焙进位图。

### 6.4 文件角色

| 文件 | 目标规格 | 用途 |
| --- | --- | --- |
| `public/koma-icon-64.png` | 64×64 RGBA | favicon、导航与 32–42px 小尺寸标识 |
| `public/koma-icon.png` | 256×256 RGBA | 应用图标和帮助 |
| `public/koma-readme-icon.png` | 512×512 RGBA | README 和文档展示 |
| `public/koma-mascot.png` | 至少 1024px、RGBA | 首页完整 2～2.5 头身 Q 版角色 |

四个文件必须来自同一黑发双丸子头角色主设，不得混用旧角色或不同画风。`koma-icon-64.png` 使用独立头部构图，再针对小尺寸导出，不能直接把全身大图机械缩放。

### 6.5 尺寸与使用规则

- 在 16、24、32、42、64px 和 1×/2× 像素密度下检查头部轮廓与识别道具。
- 16px 下允许省略眼睛细节，但外轮廓与播放标记不能糊成一团。
- 图标四周保留至少画布宽度 8% 的安全区；角色不得贴边或被圆角裁掉头部。
- 首页完整 Q 版角色桌面视觉高度建议 180–260px，不越过分析工作台或挡住文本。
- 移动端角色视觉高度建议 72–112px，空间不足时移到说明末尾，不压缩表单。
- 装饰性角色图片使用 `alt=""`。若图片承担说明，等价文字必须同时出现在 DOM 中。
- 不对角色做循环摇摆、呼吸缩放或跟随鼠标。必要微动必须由 `prefers-reduced-motion` 关闭。

### 7.2 使用规则

- Accent 不用于正文、小字号链接或大面积背景；明亮 Accent 上使用 Ink。
- Accent deep 承担焦点环、可读的强调文字和激活图标。
- Muted 仅用于辅助元数据；关键帮助、错误和说明使用 Ink 2。
- Danger 只对应失败、校验和永久删除；Warning 只对应等待、排队和需注意状态。
- 成功、处理中和选中不能只靠颜色，必须有文字、形状或进度值。
- 媒体区允许白色文字和半透明黑色字幕衬底；媒体外不建立全应用暗色主题。

## 8. 排版、间距与形状

### 8.1 字体栈

```css
--font-ui: "Avenir Next", "PingFang SC", "Hiragino Sans GB", "Noto Sans CJK SC", sans-serif;
--font-display: "Avenir Next Condensed", "Avenir Next", "PingFang SC", "Hiragino Sans GB", sans-serif;
--font-mono: "SFMono-Regular", "Roboto Mono", "Liberation Mono", Consolas, monospace;
```

字体栈使用本地与系统字体，不引入首屏依赖的远程字体。中英文切换不改变字号体系，也不通过极窄字宽压缩中文。

### 8.2 字级

| 层级 | 桌面 | 移动 | 说明 |
| --- | --- | --- | --- |
| Brand | 18/19 | 16/18 | 品牌名称 |
| Display | 48–64/0.98 | 38–48/1.02 | 首页与结果主标题 |
| Page title | 32–44/1.08 | 28–36/1.12 | 后台和弹窗大标题 |
| Section title | 20–28/1.2 | 19–24/1.25 | 工作台和结果区块 |
| Body | 14–16/1.65 | 14–16/1.6 | 主要说明与结果正文 |
| Control | 12–14/1.2 | 13–16/1.2 | 按钮、输入和选项 |
| Metadata | 9–12/1.4 | 10–12/1.4 | 时间码和非关键标签 |

正文使用 400–520，控件和小标题使用 620–720，展示标题最高约 780。中文不使用过度字距；英文等宽标签可以使用最多 `.16em` 的字距。全大写仅用于短英文元数据，不能替代中文标题。

### 8.3 间距与圆角

- 基础间距：4px。
- 常用间距：4、8、12、16、20、24、32、40、48、64px。
- 控件圆角：8px；主操作 9px；表单或小面板 10–14px；媒体最多 16px。
- 弹窗和预览的圆角不得超过 16px；移动全屏弹窗为 0。
- 胶囊仅用于语义明确且文字很短的状态，不用于容器、标题或普通按钮。
- 主要页面容器最大宽度 1280–1440px；桌面侧边留白至少 24px，移动至少 10–12px。

## 9. 共享外壳与控件

### 9.1 顶部导航

- 桌面高度 68px，移动最小高度 58px，始终有底部分隔线。
- 左侧为 Q 版小图标、Koma 文本字标和简短技术标签。
- 右侧保留语言、我的任务、管理与帮助入口；窄屏将次级入口收进现有更多菜单。
- 所有操作维持 44px 触控区域；缩成图标时提供可访问名称。
- 顶部导航可以 sticky，但不能使用模糊玻璃、重阴影或占据过多垂直空间。

### 9.2 按钮

- 主按钮默认墨黑底白字，hover 可切换为 Accent 底 Ink 字；页面每个主要任务区只保留一个主按钮。
- 次级按钮为 Surface 底、Line 边框、Ink 2 文字。
- 危险按钮使用 Danger 与 Danger soft，并在文案中明确删除含义。
- disabled 不只降低透明度；同时取消 hover 位移并保持文字可读。
- active 位移最多 1px，不使用缩放弹跳。

### 9.3 表单

- 输入高度至少 44px，标签始终可见，placeholder 不替代标签。
- focus 使用 Accent deep 边界与不超过 3px 的柔和外环。
- 错误紧邻对应字段，使用明确文本和 `role="alert"`。
- JSON 与 Schema 使用等宽字体；字号在移动端至少 16px，避免浏览器自动缩放。

### 9.4 面板

面板只用于边界、滚动或分组确有意义的内容。优先使用标题、留白和细线，不把每一个指标、标签或文件都做成悬浮卡片。阴影只属于菜单、弹窗、登录面板和画面预览等真正抬升层。

## 10. 首页

### 10.1 桌面结构

首页采用非对称 12 栏网格：说明与角色约占 5 栏，分析工作台约占 7 栏。页面第一视区同时出现核心价值、来源输入和开始按钮。

说明栏包含：

1. 一条简短的工作台标签。
2. 不超过两行的主标题。
3. 一段说明 Koma 输出内容的正文。
4. “视频 → 声音 + 画面 → 数据 + 文件”的三步流程线。
5. 完整 Q 版逐帧整理员与简短角色说明。

角色说明只解释真实工作：“看画面、听声音、按时间码整理内容”。不使用对话输入、在线状态或模型拟人化承诺。完整角色以低重心小身体落在说明栏底部，始终使用 2～2.5 头身全身构图。

分析工作台包含：

1. 本地视频 / 视频地址模式切换。
2. 对应的上传区域或 URL 输入。
3. “这次想得到什么”的自然语言输入；留空时仍运行默认总结、章节和字幕。
4. “提取信息 / 双语字幕 / 整理报告”等可独立组合的建议开关；它们补充用户要求，不是互斥预设。
5. “整理成 JSON”动作以及可编辑的 JSON 示例或 JSON Schema。
6. 当前草稿的浏览器自动保存、设为默认和恢复默认操作。
7. 持久回看提示、上传进度、错误和“开始分析”按钮。

工作台是一个连续表单。内部区块用标题和 1px 分隔线组织，不再叠套多个卡片。自由输入和建议开关共同组成最终分析要求；用户可以同时启用多个建议，也可以完全不启用。导出格式不是分析模式，公共表单不在提交前要求用户选择 JSON、CSV、Markdown、SRT 或 Text。

JSON 结构由服务端使用已配置的 Vision Provider 根据最终分析要求生成。生成前不得清空现有输入；生成失败时保留当前要求和 JSON。替换非空 JSON 前需要确认。生成期间锁定配置和分析提交，返回结果先进入编辑器草稿，只有用户确认使用后才写入并保存。编辑器提供实时校验、格式化、清空和明确的有效/错误状态；留空表示允许分析模型自行决定结构。

浏览器使用带版本号的本地配置保存自然语言要求、建议 ID 和 JSON 文本，不保存视频文件或视频地址。每次编辑自动保存草稿；用户可以将当前内容设为默认并在以后恢复。开始新任务或返回首页不清空配置，损坏或未知版本的本地数据安全回退为空配置。

### 10.2 响应式顺序

在 1050px 以下，分析工作台排在品牌说明之前，使用户先完成任务。完整 Q 版角色缩小并移到说明尾部。720px 以下表单单列，分析要求、建议开关和 JSON 入口保持可见；开始按钮占满可用宽度。320px 下不得隐藏关键标签或产生页面级水平滚动。

### 10.3 首页状态

- 空：默认显示 URL 或当前实际默认来源模式，工作台可立即输入。
- 已选择文件：显示真实文件名、大小和就绪状态。
- 上传中：显示真实上传百分比，按钮文案同步，不显示虚构剩余时间。
- 校验失败：错误靠近来源、分析要求或 JSON 编辑器入口，并把焦点留在可修正位置。
- 提交中：禁止重复提交，保留返回或失败后的重试路径。

## 11. 进度页

进度页沿用首页的说明栏 + 工作台结构，避免像跳转到另一个产品。左侧使用紧凑标题和中尺寸 Q 版角色标记；右侧显示真实进度。

进度面板必须包含：

- 服务端返回的当前阶段名称。
- `0–100` 的真实百分比。
- 服务端返回的详情文本或明确的准备状态。
- 对既有流程的概括：视频已接收、分析声音与画面、整理结果。
- 正在运行时的“返回首页并继续运行”动作。
- 失败时的翻译后错误、重试和返回动作。

进度条、阶段文本和百分比表达同一状态。更新区域使用 `aria-live="polite"` 或等效可感知机制；错误使用 `role="alert"`。不显示虚构计时、排队位置、速度或成功概率。角色保持静态，不能用角色动作代替真实阶段。

## 12. 结果页

### 12.1 桌面骨架

结果页使用主内容 `minmax(0, 1fr)` 与约 360–390px 字幕栏的双列结构。字幕栏可以 sticky，但其高度不得超出视口可操作范围。结果标题过长时允许自然换行或安全截断，不能用持续缩小字号解决所有长度。

主内容按既有数据组织：

1. 完成时间、标题与重新开始、复制回看链接、所有者删除动作。
2. AI 总结。
3. 如存在，按要求提取的数据与生成文件。
4. 时长、关键帧数、字幕行数和回看状态。
5. 内容标签。
6. 视频播放器与当前时间码。
7. 关键帧接触印样。
8. 章节列表。

上述顺序可以通过布局紧凑化，但不得伪造不存在的结果，也不得在无数据时展示假占位内容。结果数据区不放置角色插图，避免干扰视频与阅读。

### 12.2 媒体与时间导航

- 视频区域使用 Media 背景，控制、字幕和时间码保持高对比。
- 当前字幕、章节、标签和关键帧继续跳到真实时间点。
- 关键帧使用统一 16:9 比例、真实时间码和已有描述；当前帧同时用边框、标记和文本状态表达。
- 画面预览支持已有的上一张、下一张、回到该时刻和打开原图操作。
- 章节使用序号、开始/结束时间、标题和总结；无章节时显示已有空状态文案。
- 字幕按开始/结束时间和说话人信息排列；当前行具有不只依赖颜色的可见标记。

### 12.3 结构化数据与文件

- JSON 使用等宽字体、可滚动代码区域和已有复制、下载、API 操作。
- 生成文件使用紧凑列表，显示名称、格式、语言和大小；文件名过长时保留可访问的完整名称。
- 生成文件是分析结果，不是互斥的分析模式；公共分析表单不把输出格式做成选项卡或功能卡。

### 12.4 移动结果

720px 以下结果改为单列：标题与动作、总结/提取结果、视频、标签、关键帧、章节、字幕和文件按可读顺序展开。动作允许换行；删除不能与主操作位置混淆。关键帧在常见手机宽度为两列，在最窄宽度为一列。字幕不再使用占满视口的 sticky 侧栏。

## 13. 管理后台

后台共享 Paper、Ink、Accent、表单、按钮、焦点和弹窗令牌，密度更高但不更花哨。

- 未启用状态：显示真实配置要求，不提供默认密码暗示。
- 登录：使用 Q 版小图标、短说明、密码字段和单一主操作。
- 标题区：说明 Provider、密钥、永久任务和存储资产的真实范围。
- 统计区：只呈现现有活动、失败、历史数量和 Provider 链路。
- Provider：ASR 与 Vision 并列编辑；输入、select、Key 状态和保存/恢复动作统一。
- 任务表：保留状态、创建时间、Pipeline、详情、回看和删除；长内容可换行或省略，但操作保持可见。
- 任务详情：使用共享大弹窗，保留请求配置、Provider 快照、结果与文件信息。

角色不进入统计、Provider 表单或任务表。后台只在顶部品牌和登录入口使用小图标，避免干扰运维信息。

## 14. 弹窗与覆盖层

适用于 JSON 编辑器、我的任务、帮助、关键帧预览和后台任务详情。

- 桌面弹窗宽度按内容使用约 680px 或 920px，上限不超过视口安全区。
- 标题、说明、关闭按钮和主操作位置一致；关闭按钮至少 38×38px，触控区域补足到 44px。
- Escape 关闭、点击背景关闭和显式关闭按钮行为一致；需要确认的破坏性操作继续使用明确确认。
- 打开时焦点进入弹窗，Tab 不逃到背景；关闭后返回触发控件。
- 背景不可滚动，弹窗正文可滚动，标题和底部动作在长内容下保持可用。
- 520px 以下 JSON 编辑器与复杂详情使用全屏弹窗，并处理 safe-area inset。
- 覆盖层使用半透明 Ink，不使用模糊玻璃作为主要效果。

历史空状态、加载、删除中、错误与成功通知必须用真实数据和文案表达。帮助弹窗可以展示 Q 版小图标，但内容仍以步骤说明为主。

## 15. 移动端策略

### 15.1 断点

- `> 1050px`：完整非对称首页与双列结果。
- `721–1050px`：单列首页，工作台优先；结果根据可用宽度收敛。
- `≤ 720px`：紧凑导航、单列内容、44px 触控目标。
- `≤ 520px`：全屏复杂弹窗、全宽主操作、更紧凑角色。
- `≤ 360px`：关键帧单列，按钮文案保持可见且不产生横向页面滚动。

### 15.2 规则

- 页面左右安全边距为 10–12px，支持 `env(safe-area-inset-*)`。
- 表单和主要错误必须在软键盘弹出后仍可到达。
- 主操作可以在表单末尾形成全宽按钮；若使用 sticky，不能遮住错误、内容或浏览器安全区。
- 角色是辅助内容，空间不足时先缩小或移到正文之后，不能压缩表单。
- 移动端不依赖 hover；所有 hover 信息同时通过可见文字或 focus 提供。
- 标签、章节、字幕和关键帧保持真实 DOM 阅读顺序。

## 16. 动效

### 16.1 令牌

- Fast：120ms，用于颜色和边框。
- Base：160–180ms，用于菜单、按钮和小范围显隐。
- Slow：220–240ms，用于页面区块进入和弹窗。
- Ease out：`cubic-bezier(.22, 1, .36, 1)`。

### 16.2 允许

- 透明度变化。
- 最多 8–12px 的进入位移。
- 按钮 hover 最多上移 1px。
- 真实进度条宽度变化。
- 当前关键帧、字幕和章节的短暂强调。

### 16.3 禁止

- 弹跳、过冲、持续漂浮、角色呼吸缩放、视差、鼠标跟随、随机抖动。
- 不对应真实进度的无限加载动画。
- 会改变阅读位置或造成内容跳动的布局动画。

在 `prefers-reduced-motion: reduce` 下，取消非必要进入动画和位移，进度仍可通过数值和瞬时宽度表达。

## 17. 可访问性

### 17.1 对比

- 正文与背景至少 4.5:1。
- 大字号文字、控件边界、焦点和图形对象至少 3:1。
- Accent 不直接承载小字号文字；使用 Accent deep 或 Ink。
- Muted 只服务非关键元数据，关键帮助文本使用 Ink 2。

### 17.2 键盘与焦点

- 所有按钮、链接、建议开关、上传区、字幕行、章节、标签和关键帧都可通过键盘访问。
- `:focus-visible` 使用 2px Accent deep，外偏移 3px，不被 overflow 裁掉。
- 弹窗有初始焦点、焦点约束、Escape 和关闭后焦点恢复。
- 当前选项使用 `aria-pressed`、选中标记和文字/边框组合，不只改变颜色。

### 17.3 状态与图像

- 异步进度使用 `aria-live="polite"`；校验和处理失败使用 `role="alert"`。
- 装饰性图标和角色图隐藏于辅助技术；有信息意义的关键帧使用现有描述作为替代文本。
- 不自动播放有声音的媒体，不让动画成为理解流程的必要条件。
- 200% 缩放和 320px 宽度下保持操作完整，不出现页面级水平滚动。

## 18. 行为与数据契约

视觉实施必须保留以下既有行为：

- 路由 `/`、`/jobs/:id`、`/admin` 及其刷新/回看行为。
- 中英文切换、语言持久化和服务端结果语言规则。
- 本地视频与公开 URL 两种来源模式。
- 默认分析、自由输入、可组合建议、可编辑 JSON 示例/Schema，以及浏览器草稿和默认配置。
- 公共界面提交组合后的 `instruction` 与解析后的 `outputSchema`；视频分析接口继续兼容程序化调用方的 `artifactFormats`，但公共界面不主动发送它。
- `POST /api/analysis-spec/generate` 根据要求生成 JSON 结构；Provider 凭据只保留在服务端，响应不缓存。
- 上传、排队、解析、下载、检查、抽帧、音频、听写、理解、存储、完成和失败等真实服务端阶段。
- 任务轮询、返回首页继续运行、失败重试和任务历史。
- 匿名浏览器所有权、公开只读回看和所有者/管理员删除边界。
- 视频播放、字幕开关、时间跳转、关键帧预览、章节和标签同步。
- 结构化 JSON、API 地址、生成文件下载和文件元数据。
- 管理员认证、Provider 配置、Key 隐藏、环境变量恢复和任务详情。
- 除新增 JSON 结构生成接口外，既有 HTTP API、请求/响应类型、数据库、存储和 Provider 快照契约保持兼容。

布局可以调整元素顺序和密度，但不能重命名数据字段、改变权限、改变副作用或把尚未返回的数据显示为已完成。

## 19. 样式与文件组织

实施采用三个职责明确的样式入口：

| 文件 | 所有权 |
| --- | --- |
| `src/client/atelier-foundation.css` | 令牌、reset、排版、共享导航、按钮、表单、焦点、覆盖层与基础响应式规则 |
| `src/client/atelier-public.css` | 首页、进度、结果、媒体、字幕、关键帧、历史、帮助和 JSON 编辑器 |
| `src/client/atelier-admin.css` | 后台登录、统计、Provider、任务表与任务详情 |

`src/client/main.tsx` 按 foundation、public、admin 的顺序引入。每个选择器应有明确归属，不依赖多份历史样式用相同 specificity 相互覆盖。完成迁移后，旧样式不应继续参与运行时级联。

React 组件继续使用现有 `App.tsx` 与 `AdminApp.tsx` 的数据和事件逻辑。视觉拆分可以提取纯展示组件，但不能借机改变请求流程、轮询、所有权或服务端类型。

## 20. 实施顺序

1. 建立全新 Q 版角色资产、颜色、字体、间距、控件和焦点基础。
2. 重构公共顶部导航与首页工作台，完成桌面和移动顺序。
3. 对齐进度、失败和重试状态。
4. 重构结果页、媒体、关键帧、章节、字幕、结构化数据与文件列表。
5. 统一 JSON 编辑器、历史、帮助和画面预览弹窗。
6. 对齐后台登录、Provider、统计、任务表和任务详情。
7. 移除旧样式入口，验证所有路由、状态和响应式宽度。
8. 完成视觉、可访问性、功能回归和资产检查。

每一步都应保留可运行、可测试的现有功能，不以一次性大替换掩盖行为回归。

## 22. 验收标准

- Frame Atelier 的全新 Q 版角色、暖纸、墨黑、时间码和克制 Accent 在首页、进度、结果与后台保持一致。
- 新角色为 2～2.5 头身、圆润大头小身体，并且不是旧 Logo 的缩比例重绘。
- 首页第一视区包含可操作的分析工作台，角色和标题不抢占任务入口。
- 分析要求以自然语言输入和可组合建议构成；AI 生成的 JSON 可编辑、可校验并在浏览器内复用。
- 公共界面不把导出格式当作互斥的分析模式，也不要求用户为每次测试重新输入 JSON。
- Logo 在 16–64px 清晰，首页完整 Q 版角色透明、无旧角色混入、无不一致画风。
- 公共页与后台使用同一基础控件和焦点语言，后台保持更高信息密度。
- 结果页可以从总结、标签、字幕、章节和关键帧回到真实视频时间点。
- 所有空、加载、失败、删除和完成状态均由真实数据与文案表达。
- 320px 至桌面宽度无页面级水平滚动，触控目标和弹窗在移动端可用。
- 键盘、对比、减少动态效果和 200% 缩放检查通过。
- 除新增 JSON 结构生成接口外，路由、既有 API、Provider、所有权、删除、下载、存储和数据契约保持兼容。
- 测试、类型检查和生产构建通过。
