# ADR 0003：GitHub 账号工作区与私有任务

## 状态

已采纳。取代 [ADR 0002](0002-persistent-replay.md) 中的免登录提交、浏览器作为唯一归属和新任务默认公开回看决策；保留其持久化数据库、独立对象存储和显式删除规则。

## 问题

匿名浏览器 Cookie 无法在换设备或清除站点数据后恢复管理入口。旧回看链接允许任何持有者访问，不适合作为个人视频资料库的默认权限。管理员密码负责运营，不应同时成为普通用户的登录凭据。

## 决策

使用 GitHub App 的用户授权流程验证身份。Koma 不申请仓库、组织或额外账号权限，不要求仓库安装，不使用安装令牌或 App 私钥。仅从 GitHub 读取公开资料，以稳定的数字用户 ID 关联账号；用户名、显示名和头像可随再次登录更新。

浏览器通过 `/api/auth/github` 发起授权。服务端保存十分钟有效、一次性消费的 OAuth 尝试，以独立 Cookie 绑定发起浏览器，并使用 PKCE S256。回调只接受本次尝试，回跳限制为站内非 API 路径。GitHub 访问令牌只在取资料时使用，不持久化；Koma 签发自己的七天 HttpOnly 会话，只在数据库存储会话令牌哈希。会话在 HTTPS 下使用 Secure，SameSite 为 Lax。退出撤销当前会话，重新登录会替换当前会话。

网页分析、AI JSON 生成、个人历史和账号写操作都由服务端校验账号；写操作还要求 `X-Koma-Client: 1` 并检查跨站请求信息。新任务保存在当前账号下，回看、结果 JSON、视频、关键帧和文件下载逐一校验所有者或管理员身份。仅有任务 ID 不授予访问权限，当前不提供新任务公开分享开关。

`ADMIN_PASSWORD` 和管理员会话继续独立负责 Provider、密钥、全局任务和删除。GitHub 登录不会提升权限。`ANALYSIS_REQUIRE_ADMIN=true` 在已配置管理员密码时增加管理员会话要求，不能代替 GitHub 登录。本地 CLI 仍可直接调用分析流程，无需网页登录。

## 数据与旧任务

新增账号、会话、OAuth 尝试、账号任务归属和重试来源表，不重写旧任务及浏览器归属。旧任务未认领时保留原来的只读链接；登录本身不触发迁移。

用户可以明确认领当前 `koma_viewer` Cookie 能证明归属的全部旧任务。认领先将这些任务前缀中的 OSS 对象设为私有，再建立不可覆盖的账号归属；对象权限处理失败时不分配账号。缺少 Cookie、只有任务 ID、其他浏览器的记录，以及没有归属证明的旧数据，都不能通过这条路径认领。无人可证明归属的记录继续保留并由管理员管理。

新的 OSS 写入显式设置对象私有，不修改共享 Bucket 权限。Koma 的任务文件接口在完成权限校验后只返回短期签名地址，不使用公开 URL 覆盖。认领限制后续 Koma 与 OSS 源站访问，但不能收回此前分享、下载、缓存的公开内容，已签发地址也能使用到过期。

失败任务在来源 URL 或持久视频仍可用时可以重试。重试创建新任务，保留原记录，复制语言和分析要求，使用当前 Provider 配置；服务重启不自动续跑中断任务。资料库展示最近 200 项，支持浏览器端搜索和筛选。分析草稿与已保存的默认配置仍保存在当前浏览器，按账号区分，不属于跨浏览器同步范围。

## 恢复与限制

升级前暂停提交并保存一致的数据库、对象存储快照。数据库迁移可通过备份恢复，但旧服务会忽略新增账号权限，因此回滚期间必须关闭对外任务和媒体访问；确认权限保护恢复后才能放行。恢复旧快照前另存升级后的数据，不能通过删除账号归属表实现安全回滚。

账号验证不是 URL 出站隔离。导入器尚未构成完整 SSRF 防线，开放给不可信用户前仍需出站策略或可信 URL 白名单。单机按 IP 限流和 Provider 配额也继续独立生效。源码与自动化测试证明实现契约，不代表任一部署已完成 GitHub 注册、真实登录或模型分析验收。
